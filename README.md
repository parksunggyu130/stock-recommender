# 주식 추천 앱

1개월 일봉 기술적 지표로 코스피/코스닥 종목을 스크리닝해 상위 10종목을 뽑고,
그 10종목에 대해 최근 뉴스를 검색해 상위 3종목을 최종 추천하는 개인용 앱입니다.
모바일/PC 모두 브라우저에서 "앱처럼" 설치해 쓸 수 있는 PWA이고, Windows용 실행 파일(.exe)로도
바로 띄울 수 있습니다.

- 매일 아침 **07:00(KST)**: 추천 3종목을 푸시 알림으로 발송
- 매일 **16:00(KST)**: 그 3종목이 오늘 종가 기준 얼마나 올랐는지 성과 알림 발송 +
  당일 상한가(+30%) 종목 스캔 → 뉴스 기반 추정 사유 분석 → 상한가 전 5거래일 지표를
  DB에 계속 쌓아서, 오래 돌릴수록 "상한가 가기 전에 어떤 징조가 있었는지" 통계가 정교해짐

> ⚠️ 투자 참고용이며 투자 권유가 아닙니다. 투자 판단과 책임은 본인에게 있습니다.

## 추천 로직 요약

최근 1개월(약 20 거래일) 일봉을 기준으로 아래 5개 조건을 점검해 0~5점을 매기고,
점수 상위 10종목을 고릅니다.

1. 정배열 (5일선 > 20일선, 20일선 우상향)
2. RSI(14) 50~70 구간 (상승 모멘텀, 과매수 직전)
3. 최근 3거래일 내 MACD 골든크로스
4. 거래량이 20일 평균 대비 1.5배 이상 급증
5. 종가 기준 최근 20일 신고가 경신

그 10종목에 대해 (네이버 뉴스 검색 API 키를 설정한 경우) 최근 48시간 뉴스 제목/요약에서
긍정·부정 키워드를 세어 점수화하고, `기술점수*0.7 + 뉴스점수*0.3`으로 최종 top3를 뽑습니다.
뉴스 API 키가 없으면 자동으로 기술점수만으로 top3를 정합니다.

스캔 대상은 시가총액 상위 N종목(기본 500, `.env`의 `UNIVERSE_SIZE`로 조절)으로 제한해
속도를 확보하고 유동성 낮은 잡주가 섞이는 것을 방지합니다.

## 16:00 마감 체크 (성과 추적 + 상한가 분석)

- **추천 성과**: 07시에 추천한 3종목의 "추천 당시 기준가"(직전 거래일 종가) 대비 오늘
  종가 등락률을 계산해 알림으로 보내고 화면에도 표시합니다. 앱에서 "지금 마감 체크"를
  누르면 장중에도 현재가 기준으로 언제든 확인할 수 있습니다.
- **가상 투자 시뮬레이션**: "1,000만원을 07시 추천가에 3종목 균등 매수해서 16시 종가에
  매도했다면 얼마였을까"를 계산해 같이 보여줍니다 (수수료·세금·슬리피지 미반영,
  종목별 배분액보다 주가가 비싸 못 산 만큼은 현금으로 남는 것으로 계산).
- **상한가 스캔 + 사유 분석**: 코스피/코스닥 전 종목(ETF 제외) 중 당일 등락률 +29.5% 이상인
  종목을 찾아, 네이버 뉴스에서 "{종목명} 급등" 등을 검색해 최근 헤드라인과 매칭된 호재성
  키워드를 "추정 사유"로 보여줍니다. (뉴스 검색 기반 추정이며 실제 원인과 다를 수 있습니다)
- **상한가 사전 징조 축적**: 상한가가 발생하면 그날(0)부터 이전 4거래일(-1~-4), 총 5거래일치
  기술 지표 스냅샷(정배열/RSI/MACD골든크로스/거래량급증/신고가 여부, 점수)을 DB에 저장합니다.
  이 기록이 쌓일수록 "상한가 N일 전에 거래량 급증이 몇 %였는지" 같은 통계의 표본이 늘어나
  분석이 정교해집니다 — **즉, 앱을 오래 돌릴수록 이 기능의 가치가 커집니다.** 통계는 화면의
  "상한가 사전 징조 분석" 섹션과 `GET /api/limit-up/precursor-stats`에서 확인할 수 있습니다.

## 데이터 소스 (전부 무료, 키 없이 동작)

- **종목 시세/시가총액/등락률/일봉(OHLCV)**: 네이버 증권 모바일 공개 API
  (m.stock.naver.com). 로그인/키 불필요, `requests.Session`으로 커넥션을 재사용해
  500종목을 스캔해도 10여 초 안에 끝납니다.
  (참고: 처음엔 KRX 공개 데이터를 감싸는 `pykrx`를 같이 썼으나, 1) KRX 정보데이터시스템의
  일부 통계 API가 최근 KRX 회원 로그인을 요구하도록 바뀌었고, 2) 실행 파일(exe)로
  패키징했을 때 `pykrx` 호출을 수백 번 반복하면 원인 불명의 오버헤드로 급격히
  느려지는 문제가 있어 완전히 걷어내고 네이버 API 직접 호출로 통일했습니다.)
- **뉴스(선택)**: 네이버 검색 오픈 API. 무료지만 개인 발급 필요(아래 참고). 없어도 앱은 동작합니다
  (추천/마감체크는 정상 동작하고, 뉴스 사유·헤드라인만 비어있게 표시됩니다).

## 0. 실행 파일(.exe)로 바로 쓰기 — 가장 간단한 방법

이미 빌드된 실행 파일은 `backend/dist/StockRecommender/` 폴더에 있습니다.
`StockRecommender.exe`를 더블클릭하면:

1. 처음 실행 시 같은 폴더에 `.env`가 없으면 알림용 VAPID 키와 크론 시크릿을 자동 생성해
   `.env`를 새로 만듭니다 (설정 없이 바로 동작).
2. 로컬 서버(`http://127.0.0.1:8000`)가 뜨고 기본 브라우저가 자동으로 열립니다.
3. 이 창(콘솔)을 닫으면 서버가 종료됩니다. PC를 켜둔 동안만 07/16시 알림이 동작합니다
   (PC를 항상 켜두거나, 아래 "2. 무료 클라우드 배포"로 옮기면 PC를 꺼도 동작합니다).

데이터(`data.db`)와 설정(`.env`)은 exe와 같은 폴더에 저장되므로, `dist\StockRecommender`
폴더 전체를 옮기면 데이터도 그대로 유지됩니다.

(선택) 뉴스 기반 추천 사유를 보려면 그 폴더의 `.env`를 열어 `NAVER_CLIENT_ID`/`NAVER_CLIENT_SECRET`을
채워주세요 (아래 5번 참고). 휴대폰 알림은 `DISCORD_WEBHOOK_URL`을 채우는 게 가장 간단합니다
(아래 4번 참고). 코드를 수정한 뒤 새로 빌드하려면:

```powershell
cd backend
.\build_exe.bat
```

빌드 결과는 매번 `backend\dist\StockRecommender\` 에 새로 생성됩니다.

## 1. 로컬에서 소스로 실행하기 (Windows PowerShell)

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

copy .env.example .env
# .env 파일을 열어 아래 "VAPID 키 생성", "네이버 뉴스 API 키(선택)" 항목을 채워주세요.

python -m app.scripts.generate_vapid_keys
# 출력된 VAPID_PUBLIC_KEY / VAPID_PRIVATE_KEY 를 .env에 붙여넣기

uvicorn app.main:app --reload
```

브라우저에서 http://localhost:8000 접속 → "지금 추천받기" 클릭해서 동작 확인,
"지금 마감 체크"로 성과/상한가 분석 기능도 바로 확인할 수 있습니다.
PC 크롬/엣지에서는 주소창의 설치 아이콘으로 "앱 설치"가 가능하고,
휴대폰에서는 배포된 주소로 접속 후 "홈 화면에 추가"로 앱처럼 쓸 수 있습니다.

> 로컬(`localhost`)에서는 브라우저 정책상 실제 푸시 알림 수신까지 완전히 검증하기
> 어려울 수 있습니다. 알림까지 확실히 테스트하려면 2번의 배포 후 실제 주소(HTTPS)에서
> 테스트하세요.

### 테스트 실행

```powershell
cd backend
python -m pytest
```

## 2. 무료 클라우드 배포 (예: Render) — PC를 꺼도 알림이 오게 하려면

1. GitHub에 이 프로젝트를 올립니다 (`.env`는 `.gitignore`에 포함되어 있어 올라가지 않습니다).
2. [Render](https://render.com)에서 "New Web Service" → 이 저장소 선택 →
   Environment: **Docker**, Dockerfile 경로: `backend/Dockerfile`, 빌드 컨텍스트: 저장소 루트.
3. Render의 "Environment" 탭에서 `.env.example`에 있는 항목들을 그대로 등록합니다.
   - `RUN_INPROCESS_SCHEDULER` 는 `false` 로 두는 것을 권장합니다. (이유는 아래 3번 참고)
4. 배포되면 `https://<서비스명>.onrender.com` 같은 주소가 생깁니다. 이 주소로 접속해
   테스트합니다.

Render 등 완전 무료 플랜은 일정 시간 트래픽이 없으면 서버가 잠들 수 있어,
서버 안에서 도는 스케줄러(APScheduler)가 매일 정확한 시각에 깨어난다는 보장이 없습니다.
그래서 아래 3번처럼 외부 무료 크론으로 깨워주는 방식을 함께 씁니다.

## 3. 매일 07:00 / 16:00 알림을 위한 외부 무료 크론 설정 (cron-job.org)

1. [cron-job.org](https://cron-job.org)에 무료 가입.
2. 크론잡 2개 생성:
   - **아침 추천**: URL `https://<배포주소>/api/cron/daily`, Method `POST`,
     Header `X-Cron-Secret: <.env의 CRON_SECRET 값>`, 스케줄 매일 07:00 Asia/Seoul.
   - **마감 체크**: URL `https://<배포주소>/api/cron/eod`, Method `POST`,
     Header `X-Cron-Secret: <.env의 CRON_SECRET 값>`, 스케줄 매일 16:00 Asia/Seoul.
3. 이 크론이 호출되면 서버가 깨어나 계산을 수행하고, 아직 발송 전이면 구독자에게
   푸시를 보냅니다. 같은 날 이미 발송했다면 중복 발송하지 않습니다.

> `/api/cron/daily`는 종목 500개를 스캔하느라 약 20초 정도 걸릴 수 있습니다.
> cron-job.org가 응답을 기다리다 타임아웃으로 표시하더라도, 서버는 계속 계산을 진행해
> 실제로는 정상적으로 추천/알림이 처리됩니다.

내 PC를 상시 켜두고 직접 서버(또는 exe)를 돌릴 경우에는 `RUN_INPROCESS_SCHEDULER=true`로
두면 APScheduler가 알아서 매일 07:00 / 16:00(Asia/Seoul)에 실행하므로 외부 크론 없이도
동작합니다.

## 4. (선택, 추천) 디스코드로 알림 받기 — 가장 간단한 방법

브라우저 푸시(VAPID)는 HTTPS + 알림 권한 허용 + PWA 설치가 필요해 설정이 다소 번거롭고,
휴대폰마다 다시 설정해야 합니다. **디스코드 웹후크를 쓰면 훨씬 간단하게 휴대폰 알림을
받을 수 있습니다** (디스코드 앱이 이미 폰에 깔려 있고 알림도 기본적으로 켜져 있으니까요).

1. 디스코드에서 알림 받을 채널(개인 서버를 하나 만들어도 됩니다) → 채널 설정 →
   "연동" → "웹후크" → "새 웹후크" → "웹후크 URL 복사"
2. `.env`의 `DISCORD_WEBHOOK_URL`에 그 URL을 붙여넣기 (클라우드 배포 시 Render
   환경변수에도 동일하게 등록)
3. 이후 07시/16시 알림이 (설정했다면) 브라우저 푸시와 함께 디스코드로도 발송됩니다.

이 방법은 PC를 꺼도 되고, 클라우드에 배포만 되어 있으면 휴대폰 어디서든 디스코드
앱 알림으로 받을 수 있어 가장 손이 덜 갑니다.

## 5. (선택) 네이버 뉴스 검색 API 키 발급

1. https://developers.naver.com/apps → 애플리케이션 등록
2. 사용 API: "검색" 선택
3. 발급받은 Client ID / Client Secret 을 `.env`의 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`에 입력

키를 등록하지 않으면 top3는 기술점수만으로 정해지고, 상한가 종목의 "추정 사유"는
빈 상태로 표시됩니다 (앱 자체는 정상 동작).

## 주요 API 한눈에 보기

| 목적 | 엔드포인트 |
|---|---|
| 오늘의 추천(top10/top3) 조회 | `GET /api/recommendations/today` |
| 추천 수동 재계산 | `POST /api/recommendations/refresh` |
| 마감 체크 수동 실행 (성과+상한가) | `POST /api/eod/refresh` |
| 오늘 추천 성과 조회 | `GET /api/performance/today` |
| 오늘 상한가 종목+사유 조회 | `GET /api/limit-up/today` |
| 상한가 사전 징조 누적 통계 | `GET /api/limit-up/precursor-stats` |
| 외부 크론: 아침 추천+알림 | `POST /api/cron/daily` (헤더 `X-Cron-Secret`) |
| 외부 크론: 마감체크+알림 | `POST /api/cron/eod` (헤더 `X-Cron-Secret`) |

## 알아둘 점 / 한계

- 코스피/코스닥 상장 종목만 대상입니다 (ETF/ETN 제외).
- 주말·공휴일에는 최근 거래일 데이터를 그대로 보여줍니다.
- 상한가 판정은 등락률 +29.5% 이상으로 (반올림 오차 감안) 근사 판정합니다.
- 상한가 "사유"와 "징조"는 뉴스 검색·통계 기반 추정이며, 인과관계를 보장하지 않습니다.
  이벤트가 적을 때는 통계 신뢰도가 낮고, 앱을 오래 돌려 이벤트가 쌓일수록 신뢰도가 올라갑니다.
- 무료 공개 데이터/스크래핑 기반이라 데이터 제공처가 페이지 구조를 바꾸면
  `backend/app/data/krx.py`, `news.py` 쪽 수정이 필요할 수 있습니다.
- 실행 파일(exe)은 PC가 켜져 있고 그 프로세스가 실행 중일 때만 07/16시 알림이 동작합니다.
